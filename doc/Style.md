# 编码规范

如果有在设计上不应该触发的分支，直接抛出assertion error

有一些检查在性能关键的函数上会产生一些不可接受的消耗，此时应该通过assert来对条件进行假设，并在启用ea的情况下对其进行反复的验证

在开发annotation processor相关的功能时，不能依靠assert来假定情况正确，应该尽可能在需要处插入运行时检查来确保数据的合法性，编译期检查
对于编译性能的影响是微乎其微的，大可不必在意

可读性是第一规范，整体代码以可维护性作为第一设计准则

如果能够有条件做到常量折叠，一定要去追求，在设计时就需要考虑到这方面，而不是在是实现时去尽量靠拢

抛出异常时，信息尽可能简洁，以代码逻辑为第一基准而不是通过异常的具体信息去做定位，使用格式为
err msg: err-value
让开发者通过具体代码行去定位问题，消息的首字母不需要大写，以保持和jdk内部的一致性
